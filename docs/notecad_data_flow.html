From a voice note to the right branch

How one spoken note travels from the desktop recorder through the NoteCad brain, splits into events, finds its place in the owner's own map, and turns into notes, tasks and alerts that go to the right person, while the mind map lights up the nodes it changed. Every box below is running code on WABAKIPI: apps/desktop, services/brain and services/companion, with Gemma 4 and Whisper on the RTX 4060.

The whole stack on one desktop

One command, services\start_notecad.ps1, starts everything below in order and waits until each part answers. The brain also serves the desktop app, so there is no separate web server.

1 · The pipeline

A capture keeps one id from the phone to the database, so a dropped upload or a re-run job never writes twice. Each event inside the note is routed on its own.

queued→transcribing→routing→appliedorneeds_revieworfailed· laterundone

2 · Where the actions land, and who gets the work

Apply writes every action in one transaction and stores an inverse for each, so Undo reverses the whole note. Tasks are delegated by name; alerts climb the tree.

3 · What the owner sees in the tree

Colour is computed from data, never set by hand. A problem filed on a channel turns its parent the same colour; every ancestor above shows a dot for the worst thing below it.
